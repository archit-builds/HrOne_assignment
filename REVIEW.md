# REVIEW.md

Defects found in the starter `app/main.py`, found by reading the code against `openapi.yaml` / `DATA_MODEL.md`.
Every fix has a test in `tests/test_api.py` (the test name is given where useful).

| # | Where (function) | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Floors to whole minutes **before** comparing with the grace period, so the "strictly more than 10:00" rule is lost. | Shift 09:30, punch-in 09:40:01 returns 0 (should be 10). | Compare raw elapsed seconds with 600 first, then floor to minutes. (`test_late_rule`) |
| 2 | `compute_late_minutes` | Builds shift start with `punch_in.replace(hour, minute)`, i.e. on the punch-in's own calendar day and in the punch's own time zone (naive local). Wrong for overnight shifts and for any server not running in IST. | Shift 22:00-06:00, punch-in 05:30 next morning is compared with 22:00 *that same day*, giving a negative number. | `shift_bounds()` anchors the shift to the attendance date in IST; all datetimes are UTC-aware. |
| 3 | `compute_work_hours` | Built-in `round()` on a float: not half-up (4h 0m 18s = 4.005 h gives 4.0, should be 4.01). Also uses sub-second precision. | Punch-out 18 seconds past 4 hours. | Whole seconds -> `Decimal` -> `ROUND_HALF_UP` (`round_half_up`). (`test_work_hours_rounds_half_up`) |
| 4 | `compute_overtime` | Subtracts an IST-aware datetime from a naive one: `TypeError` (HTTP 500) as soon as it is used. | Any punch-out. | Everything is UTC-aware (`MongoClient(tz_aware=True)`, `from_ms`). |
| 5 | `compute_overtime` | No 30-minute minimum, and the shift end is always on the record date, so an overnight shift's end (next day) is wrong. | Shift ends 18:30, punch-out 18:50 returns 20 (should be 0); 22:00-06:00 shift punched out 06:40 next day returns 1480 (shift end taken as 06:00 of the record date) instead of 40. | `compute_overtime` returns 0 under 30 min; `shift_bounds()` moves an overnight shift end to the next day. (`test_overtime_threshold`, `test_overnight_punch_out`) |
| 6 | `/health` | Always returns 200, never talks to MongoDB. | Stop MongoDB: still `ok`. | Ping MongoDB, return 503 on failure. |
| 7 | `EmployeeIn` | Bare `str` fields: no `emp_code` pattern, email/date/time format, lengths, or `shift_start != shift_end`. | `emp_code: "x"`, `joined_on: "2026-02-30"`, `shift_start == shift_end` are all accepted with 201. | Pydantic constraints for every field in the OpenAPI schema plus a model validator for the shifts. (`test_employee_validation`) |
| 8 | `create_employee` | Check-then-insert with no unique index: two parallel requests can both insert. | Send 8 identical POSTs at once, several 201s. | Unique index on `emp_code`; catch `DuplicateKeyError` -> 409. (`test_concurrent_employee_create`) |
| 9 | `create_employee` | `datetime.now()` is server-local and naive (not a UTC instant); `created_at` is returned as a datetime string instead of epoch ms. | Response `created_at` is `"2026-..."` text. | `now_utc()` stored; the response converts to epoch ms (`employee_to_api`). |
| 10 | `list_employees` | `skip = page * page_size` skips the whole first page (should be `(page-1)*page_size`). | `?page=1` never returns the first employee. | Fixed formula. |
| 11 | `list_employees` | `total` is `count_documents({})`, ignoring the department filter. | `?department=Eng` shows `total` of all employees. | Count with the same query as the listing. (`test_employee_created_at_is_epoch_ms_and_listing`) |
| 12 | `list_employees` | No sort (results are in natural order); `page=0` or `page_size=-5` are unvalidated (negative skip raises a server error); no max page size. | `?page=0`, `?page_size=1000`. | `sort("emp_code")`; `Query(ge=1)` and `le=100` give 422. |
| 13 | `punch_in` | Unknown employee: `emp` is `None`, then `emp['shift_start']` raises `TypeError` -> 500. | Punch in with `emp_code: "EMP9999"`. | 404 via `get_employee_or_404`. |
| 14 | `PunchInIn` / `punch_in` | `punched_at` is an unchecked `int`: seconds, huge or negative values accepted; `if body.punched_at` treats `0` as "not sent" and silently uses now; floats/strings coerced. `status` is any string (`"ABSENT"`, `"foo"` accepted). | `punched_at: 0`, `1783312500` (seconds), `1.5`, `"123"`; `status: "ABSENT"`. | `StrictInt` with the 1e11..4.1e12 range (`is not None` check instead of truthiness); `status` is a `Literal` of the three presence values. (`test_punch_in_errors`) |
| 15 | `punch_in` | `fromtimestamp()` / `datetime.now()` use the server's local zone; `date` is the local calendar day rather than the IST day, and ignores the overnight rule (R1); instants are not truncated to whole seconds. | Server in UTC: a punch at 00:30 IST gets yesterday's date. Night shift punch at 05:30 gets the wrong day. | `from_ms` (UTC, truncated) and `attendance_date()` (IST + overnight rule). (`test_overnight_attendance_date`, `test_punch_in_truncates_milliseconds`) |
| 16 | `punch_in` | Check-then-insert with no unique `(emp_code, date)` index: parallel punch-ins can create two records. | 8 parallel identical punch-ins. | Unique index `(emp_code, date)`; insert and catch `DuplicateKeyError` -> 409. (`test_concurrent_punch_in`) |
| 17 | `punch_in` | Response adds a synthetic `id` (the ObjectId) and returns `punch_in` as a datetime string, not epoch ms. | Response contains `"id"`. | `attendance_to_api` returns only contract fields, instants as epoch ms. |
| 18 | `list_attendance` | Loads **every** matching document into Python, sorts and slices there, and `total = len(docs)`. Does not scale to 100k records. | 100k documents per request. | `find().sort().skip().limit()` plus `count_documents`, all in MongoDB, backed by indexes. |
| 19 | `list_attendance` | Sorts by `date` descending only (no `emp_code` ascending tie-break); `date_from > date_to` not rejected; dates, `status` and page parameters not validated; `if emp_code:` treats an empty string as "no filter". | Two records on one date come back in arbitrary order; `date_from=2026-09-01&date_to=2026-01-01` returns 200. | Sort `{date: -1, emp_code: 1}`; `DateStr`, `Status`, `Page`, `PageSize` types; explicit 422 for inverted range; `is not None` checks. (`test_attendance_list`) |
| 20 | `list_attendance` | Returns `_id` as `id` and raw datetimes / missing `history` and `half_day` for legacy documents. | Response has `id`, string timestamps; legacy documents lack fields. | `attendance_to_api` (defaults `history=[]`, `half_day=False`, missing minutes = 0). (`test_legacy_record_defaults`) |
| 21 | module setup | No indexes are created anywhere, so every query above was a collection scan, and uniqueness could not be enforced. `MongoClient` returns naive datetimes. | `explain()` shows `COLLSCAN`. | Idempotent `create_indexes()` in the app lifespan; `tz_aware=True`; short server-selection timeout so `/health` can answer 503. |
| 22 | missing endpoints | Punch-out, PATCH, the four analytics endpoints and the explain endpoint did not exist. | 404 / 405. | Implemented (see README). |

## Looked at and judged not to be a defect

- `load_dotenv()` does not override variables already set in the environment, which is exactly the required precedence (real env vars win).
- Plain `def` endpoints with PyMongo: FastAPI runs them in a thread pool, so the event loop is not blocked, and `MongoClient` is thread-safe.
- `{"_id": 0}` projection in `list_employees` and `doc.pop("_id")` in `create_employee`: correct, `_id` must not be returned.
- `status_code=201` on the two POST routes matches the contract.
